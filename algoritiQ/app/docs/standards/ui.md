# 02 — UI standards

Counter tablet UI: used all day by non-technical staff, under time pressure, in Bengali.

## Widgets

- Widgets are dumb: MUST NOT contain business logic or call DB / channels / HTTP.
- Extract **widget classes**, not helper methods that return `Widget`.
- `build()` ≤ ~80 lines; file ≤ 300 lines. Split by responsibility.
- `const` constructors wherever possible. Stable `Key`s in dynamic lists. Use `ListView.builder` for lists.
- Don't do work in `build()` (no parsing, sorting, I/O). Rebuild narrowly (`ref.watch(x.select(...))`).
- Dispose every controller, `FocusNode`, subscription.

## Design system

- Material 3. All colors, text styles, spacing, radii come from `core/theme` tokens.
- MUST NOT hardcode colors, font sizes, paddings, or magic numbers in widgets.
- Spacing on a 4/8 dp grid. One `ThemeData` (light first; dark optional).
- Reuse shared components in `core/widgets` before creating new ones.
- Logo: always use `BrandLogo` (`.wordmark` / `.symbol`); it switches navy/white variants by theme. Never hardcode logo files or colors. Brand colors live in `core/theme/brand_colors.dart`; brand font (Plus Jakarta Sans, OFL) is bundled in `assets/fonts`.
- Opening screen = native launch screen only (no Flutter splash). It shows an animated vector wordmark (`splash_wordmark_animated.xml`, Android 12+; static `splash_wordmark.xml` below) generated by `tool/splash_wordmark/`. Regenerate after logo/font changes; keep the animation duration in sync with `MainActivity.kt`.
- Buttons have plain text labels — no arrow icons or `->`. Don't repeat the product name in screen copy when the logo is already shown.
- Spacing, radii and breakpoints: `Spacing`, `Radii`, `Breakpoints` in `core/theme`. Primary actions use the filled button from the theme (white label on `BrandColors.coralAction`, AA contrast); don't restyle it per screen.
- **Loading:** use `BrandLoader` (three dots lit in turn, like tokens being called; coral lit dot) for every wait — never `CircularProgressIndicator`. A button that starts async work is a `LoadingButton` (keeps its size, ignores taps while loading). Both live in `core/widgets`, respect the system "remove animations" setting, and take a localized `semanticLabel`.
- Input fields carry no example text (no sample names or places); the label says what goes there. Instructional hints with no data ("Paste or type the key") are fine.
- Form pages use `CardPage` (fixed top bar with logo and language toggle, then one centred card that scrolls; two columns on wide landscape) and `StepProgress` for multi-step flows. First-time setup lives in `features/clinic` (profile, chambers, ready).
- Language toggle: `LanguageSwitcher` (`core/widgets`); the choice is saved by `LocaleController`.
- **Toaster:** every result of a form submit or other action the person should know about (saved, copied, connected, failed) goes through the one app-wide toaster, `toastControllerProvider` in `core/toast`: `success`, `error` or `info` with a **localized** message. MUST NOT use `SnackBar` or `ScaffoldMessenger`. At most **5** show at once (the oldest goes when a sixth arrives); the same message is not stacked twice; success/info fade after about 4.5 s, errors stay 8 s; each has a close control and is announced to screen readers. It is mounted once in `MaterialApp.builder`, so it sits above dialogs and bottom sheets, and works in light and dark themes and any screen size. A toast is feedback, not the only place an error lives: a field's own validation error stays under the field, and a state the person must act on (printer not connected) stays on the page as well.
- **Popups:** every popup (confirmation, short form, details) uses the one reusable `AppDialog` (`showAppDialog` in `core/widgets/app_dialog.dart`); MUST NOT use `AlertDialog` or a hand-built `Dialog`. It has three parts: a **fixed header** (title and a close control), a **fixed footer** (the action buttons, primary last; none = no footer) and a **body between them that scrolls only when it does not fit**, so the header and the buttons are never pushed off screen. Its size comes from the screen, never fixed pixels (`DialogSize`): in **portrait** up to 90% of the width and 70% of the height, in **landscape** up to 55% of the width and 85% of the height, never narrower than 280 dp or wider than 640 dp, and the height shrinks to leave room for the keyboard. It shrinks to its content when that is smaller. Colours come from the theme, so it works in light and dark. A destructive or outward action (print, send, delete) asks first in an `AppDialog`; a bottom sheet is for choosing from a list (e.g. the printer picker), not for confirming. Test every new popup in portrait and landscape, light and dark, with a body long enough to scroll.
- Support **light and dark** themes (`ThemeMode.system`); verify every screen in both.

## Layout (tablet-first, any Android)

- Responsive: `LayoutBuilder`/`MediaQuery` + breakpoints; support landscape and portrait. No fixed-pixel screens.
- App MUST still work on phones and small screens (minSdk 21 devices) — never assume the Honor Pad X7 size.
- Touch targets ≥ 48×48 dp, with spacing between destructive and primary actions.
- Respect safe areas / system bars; no overflow at text scale 1.0–2.0.

## UX for the counter

- Core flow (create + print token) in **≤ 2 taps**; primary action large and obvious.
- Serial numbers large, high contrast, readable from a distance.
- Always show system health: session open, printer, TV, laptop connection.
- Destructive actions (cancel, skip, end session) need confirmation or undo.
- Every async screen handles **loading / empty / error / data** — no blank screens or infinite spinners.
- Show printer failure as `FAILED` with a **Reprint** action; never block queue actions on it.
- Public/queue views show the **serial number only** — no patient names/phones.

## Localization (Bengali + English)

- All user-visible strings via ARB (`l10n/app_bn.arb`, `app_en.arb`) — no string literals in widgets.
- Bundle **Noto Sans Bengali**; verify conjuncts and line height aren't clipped.
- Format numbers/dates via `intl`; support Bengali digits where product requires.
- Error messages are human, localized, actionable — never raw exception text.

## Accessibility

- `Semantics` labels on icon-only buttons and custom widgets.
- Contrast ≥ 4.5:1 (text), ≥ 3:1 (large text/icons). Don't convey state by color alone.
- Logical focus order; keyboard/external-input friendly.

## Navigation & performance

- Declarative routes in one place (`go_router`); no scattered `Navigator.push(MaterialPageRoute(...))`.
- Heavy work (receipt bitmap rendering, large parsing) off the UI isolate (`compute`/`Isolate.run`).
- Keep animations short and purposeful; none in the critical token flow.
