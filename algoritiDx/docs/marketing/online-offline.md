# Online + Offline deployment model

## 1. Customer and deployment

- For single-center and multi-branch diagnostic organizations wanting permanent local use and optional cloud services.
- Proposed branch policy: no fixed plan-based branch limit; license and charge each branch separately, with deployment capacity confirmed before purchase.
- Each branch works locally and synchronizes with the cloud when connected and cloud service is active.
- Internet outages delay cross-branch updates, but local work continues.
- The customer supplies local servers, LAN, power backup, and internet. Failure of these can interrupt local work.

## 2. Three separate entitlements

| Item | What it includes |
| --- | --- |
| Permanent local license | Local use of the purchased version and upgrades received under valid upgrade coverage |
| Software upgrade coverage | New local versions and standard features for the first year; optional paid annual extension afterward |
| Cloud service | Remote cloud access, branch synchronization, cloud backups, and defined support; first year included, optional annual renewal afterward |

- All standard features available at purchase are included.
- Local features already received remain usable when upgrade coverage expires.
- Cloud renewal does not automatically extend local software upgrade coverage.
- Local upgrade coverage can be extended without renewing cloud service.
- Renewals are annual, not monthly.
- Renewing cloud service does not grant new local features through synchronization.
- Patient data belongs to the customer. Source-code ownership and resale rights are excluded.

## 3. Proposed pricing

| First branch: local license, setup, training, first-year cloud and upgrades | ৳50,000 upfront |

| Optional cloud renewal from year two: first branch | ৳20,000/year |
| Optional cloud renewal: each additional branch | ৳15,000/year |
| Optional annual software upgrade extension | To be priced before launch |

No separate setup fee. Three branches cost ৳120,000 upfront; optional cloud renewal afterward totals ৳50,000/year. Upgrade extensions are separate.

An additional branch is a separate operating location within the same organization, not a counter or department. Separate businesses require separate base purchases. Hardware, SMS, migration, custom work, instrument integrations, extra training, and on-site visits are separately quoted unless included.

## 4. If coverage expires

- **Cloud expires:** local work, records, exports, and local backups continue. Cloud access, synchronization, cloud backups, and cloud-service support stop after the agreed grace period.
- **Upgrade coverage expires:** the latest legitimately received local version continues working; new local versions require paid coverage or an agreed upgrade purchase.
- Cloud and upgrade coverage expire independently; expiry of one does not cancel the other.
- Expiry does not delete local patient data.

## 5. Terms to finalize

- Set upgrade-extension pricing, start dates, and reactivation terms after a coverage gap.
- Define supported local versions for cloud synchronization; old versions cannot be supported indefinitely. Disclose any required paid upgrade before cloud renewal.
- Define defect/security-fix obligations separately from paid feature upgrades.
- Confirm support limits, local backup responsibilities, recovery, warranty, license transfers, taxes, and payment terms.
- Define grace periods, cancellation, cloud-data export and retention, and safe synchronization after a gap.
